**Omnier** is a **CRM for Agents**: **Claude** reads and updates your **companies, contacts, and deals** through a single connection. Your data lives in one **cloud workspace**.

- **In Claude** — you drive pipeline work in **plain language** (research, follow-ups, updates). Claude calls Omnier; Omnier is the source of truth.
- **In the web app** — **[app.getomnier.com](https://app.getomnier.com)** shows **activity, records, and context** in one place.

**Who it is for:** founder-led and small teams doing outbound, demos, and deal tracking who want the CRM **behind** the conversation, not another tab to re-type into.

## Data model

Schema lines up with **`read_skill`**: `deals`, `companies`, `contacts`, `notes`, `tasks`, `activity`. Every table also carries the usual system fields (`id`, `created_at`, and `user_id` where applicable); the **Key properties** column lists the main business columns only, by name.

| Object | Description | Key properties |
| --- | --- | --- |
| `deals` | Opportunity in a pipeline | `value`, `currency`, `expected_close_date`, `stage_id`, `name`, `probability`, `last_activity_at`, `next_follow_up_at`, `lost_reason`, `won_reason`, `deal_source`, `deal_type`, `momentum`, `agent_brief`, `latest_activity` |
| `user_deal_stages` | Stage row for a kanban | `name`, `order_index` |
| `user_pipelines` | Named pipeline | `pipeline_name` |
| `deal_update_logs` | Audit line when a deal changes | `update_summary`, `deal_id` |
| `companies` | Account / organization | `name`, `description`, `website`, `industry`, `employee_count`, `location`, `yc_batch`, `funding_stage`, `company_stage`, `icp_fit`, `icp_fit_reason`, `outreach_status`, `owner_id`, `updated_at` |
| `company_update_logs` | Audit line when a company changes | `update_summary`, `company_id` |
| `companies_deals` | Many-to-many company ↔ deal | `company_id`, `deal_id` |
| `contacts` | Person | `first_name`, `last_name`, `email`, `linkedin_url`, `title`, `phone`, `location`, `timezone`, `last_contacted_at`, `contact_source` |
| `contact_update_logs` | Audit line when a contact changes | `update_summary`, `contact_id` |
| `contacts_companies` | Many-to-many contact ↔ company | `contact_id`, `company_id` |
| `deals_contacts` | Many-to-many deal ↔ contact | `deal_id`, `contact_id` |
| `notes` | Note body | `note_body`, `title` |
| `notes_deals` | Note attached to a deal | `note_id`, `deal_id` |
| `notes_contacts` | Note attached to a contact | `note_id`, `contact_id` |
| `notes_companies` | Note attached to a company | `note_id`, `company_id` |
| `tasks` | Task on a parent record | `title`, `content`, `assigned_to`, `due_date`, `status`, `parent_type`, `parent_id`, `updated_at`, `task_priority` |
| `activity` | Feed row (payload in `content`) | `content` |

### How objects connect

| Connection | Detail |
| --- | --- |
| `deals` → `user_deal_stages` | `deals.stage_id` references `user_deal_stages.id` |
| `deals` ↔ `companies` | Through `companies_deals` (`company_id`, `deal_id`) |
| `contacts` ↔ `companies` | Through `contacts_companies` (`contact_id`, `company_id`) |
| `contacts` ↔ `deals` | Through `deals_contacts` (`contact_id`, `deal_id`) |
| `notes` ↔ `deals` / `contacts` / `companies` | Through `notes_deals`, `notes_contacts`, `notes_companies` |
| `tasks` → contact, company, or deal | `parent_type` + `parent_id` point at the parent row |
| `deal_update_logs` → `deals` | `deal_id` |
| `company_update_logs` → `companies` | `company_id` |
| `contact_update_logs` → `contacts` | `contact_id` |
| `activity` | Scoped to the user; `content` is JSON that can reference deals, companies, and contacts in the feed |
